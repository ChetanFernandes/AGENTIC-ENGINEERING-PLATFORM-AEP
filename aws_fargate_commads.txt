15. Create the ECS task execution role
    - Check whether the role already exists
        - aws iam get-role --role-name ecsTaskExecutionRole
    
    - Create the trust policy
        - (
                                    echo {
                                    echo   "Version": "2012-10-17",
                                    echo   "Statement": [
                                    echo     {
                                    echo       "Effect": "Allow",
                                    echo       "Principal": {
                                    echo         "Service": "ecs-tasks.amazonaws.com"
                                    echo       },
                                    echo       "Action": "sts:AssumeRole"
                                    echo     }
                                    echo   ]
                                    echo }
                                    ) > ecs-trust-policy.json

    - Verify the file was created - type ecs-trust-policy.json

    - Create the IAM role - aws iam create-role --role-name ecsTaskExecutionRole --assume-role-policy-document file://ecs-trust-policy.json
       - We are creating an identity called ecsTaskExecutionRole.
       - But simply creating the role does not give it permission to access AWS resources.
       - We are defining: a. What is the role's name? b. Which AWS service is allowed to assume (use) this role?
       - The ecs-trust-policy.json defines the trust relationship.
       - I am allowing ECS tasks to assume and use this role." 
       - This is called a Trust Policy.

    - Attach the required AWS policy - aws iam attach-role-policy --role-name ecsTaskExecutionRole --policy-arn arn:aws:iam::aws:policy/service-role/AmazonECSTaskExecutionRolePolicy
       - Now we are assigning permissions to the role.
       - This AWS-managed policy allows ECS to:
            - Authenticate with Amazon ECR.
            - Pull Docker images from ECR.
            - Create CloudWatch log streams.
            - Write container logs to CloudWatch Logs.
       - This is called a Permissions Policy. 

    -  Verify the attachment
        -  aws iam list-attached-role-policies --role-name ecsTaskExecutionRole --output table -

     - An EC2 Instance Profile is required because it is the mechanism AWS uses to attach an IAM role to an EC2 instance. 
     - Instance Profile attaches those permissions to EC2.

     - What happens if we don't create an instance profile?
        - EC2 won't receive the IAM role through this mechanism.
        - The SSM Agent won't have the required IAM permissions to register the instance.
        - The instance may not appear as Online in Systems Manager.
        - Our port-forwarding command may fail because SSM cannot establish a session.
        
     - The key takeaway: IAM Role defines permissions; Instance Profile attaches those permissions to EC2.

68 - Add the IAM role to it:

     - aws iam add-role-to-instance-profile --instance-profile-name AEP-New-SSM-Tunnel-Profile --role-name AEP-New-SSM-Tunnel-Role

     - Wait briefly for IAM propagation: timeout /t 15

69 - Get the latest Amazon Linux 2023 AMI. We'll use Amazon Linux 2023, which supports the SSM Agent.
     - for /f "delims=" %i in ('aws ssm get-parameter --name /aws/service/ami-amazon-linux-latest/al2023-ami-kernel-default-x86_64 --region us-east-1 --query "Parameter.Value" --output text') do set AMI_ID=%i

     - echo %AMI_ID%

70 - Launch the new EC2 instance
     - aws ec2 run-instances --image-id %AMI_ID% --instance-type t3.micro --subnet-id %SUBNET_ID% --security-group-ids %TUNNEL_SG% --iam-instance-profile Name=AEP-New-SSM-Tunnel-Profile --associate-public-ip-address --tag-specifications "ResourceType=instance,Tags=[{Key=Name,Value=AEP-New-SSM-Tunnel-Instance}]" --region us-east-1
    The command creates:
            - One new EC2 t3.micro instance.
            - Amazon Linux 2023 operating system.
            - New tunnel security group.
            - New SSM IAM instance profile.
            - Public IP for outbound SSM connectivity.

71 - Copy the returned InstanceId and set it:
        - set INSTANCE_ID=i-xxxxxxxxxxxxxxxxx

72 - Wait until EC2 is running

        - aws ec2 wait instance-running --instance-ids %INSTANCE_ID% --region us-east-1

73 - Check the instance:
       - aws ec2 describe-instances --instance-ids %INSTANCE_ID% --region us-east-1 --query "Reservations[0].Instances[0].[InstanceId,State.Name,PrivateIpAddress,PublicIpAddress]" --output table

74 - Wait for SSM to register the instance

       - aws ssm describe-instance-information --region us-east-1 --query "InstanceInformationList[?InstanceId=='%INSTANCE_ID%'].[InstanceId,PingStatus]" --output table
       - Expected status: Online

75 - Create the SSM tunnel configuration

      - Create a new configuration file:

      -    (
            echo {
            echo   "host": ["aep-postgres.cmpwo8c6ov6h.us-east-1.rds.amazonaws.com"],
            echo   "portNumber": ["5432"],
            echo   "localPortNumber": ["15433"]
            echo }
            ) > ssm-params-new.json

76 - Verify:
     - type ssm-params-new.json

77 - Check that local port 15433 is free

     - netstat -ano | findstr :15433

     - If there is no output, continue.

78 - Establish the new secure tunnel

     - aws ssm start-session --region us-east-1 --target %INSTANCE_ID% --document-name AWS-StartPortForwardingSessionToRemoteHost --parameters file://ssm-params-new.json

     - Expected output
            Starting session with SessionId: ...
            Port 15433 opened for sessionId ...
            Waiting for connections...
     - Keep this CMD window open.

81 -  A few important notes:
        - RDS remains private; we are not making it publicly accessible.
        - The EC2 security group has no inbound rules.
        - The EC2 instance needs outbound connectivity to SSM endpoints. Our selected subnet's internet gateway route provides this.
        - The RDS security group allows port 5432 from the new EC2 security group.
        - Stop the EC2 instance when you no longer need the tunnel to reduce compute charges.
